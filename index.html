Why Requests + BeautifulSoup instead of Playwright/Scrapy?

Both targets (Books to Scrape & Quotes to Scrape) are server-side rendered HTML with zero JavaScript hydration required. Using Playwright or Selenium would introduce unnecessary headless browser overhead, huge memory footprints, and fragile binary dependencies. Scrapy is great for massive enterprise spiders, but for a clean, maintainable, interview-ready pipeline, requests.Session + BeautifulSoup provides full transparency, standard Python readability, and zero bloat.

How does pagination work without hard-coding page counts?

Rather than calculating an arbitrary range like range(1, 51), both scrapers use dynamic pointer crawling. For Books to Scrape, we query li.next > a; for Quotes, li.next > a. We resolve the relative link using urllib.parse.urljoin(current_url, next_href). When the 'next' DOM node is absent, the while loop cleanly terminates.

How are missing HTML fields and network errors handled?

We wrap network requests in an HTTPAdapter configured with a 3-retry exponential backoff for 500, 502, 503, 504 errors. Network exceptions (requests.RequestException) are caught per page—logging the error and breaking gracefully rather than crashing the pipeline. In DOM parsing, elements use safe selection (tag.select_one(...)) with ternary fallback to None, ensuring missing nodes never trigger AttributeError.

How does duplicate detection work under formatting differences?

We construct a composite key from source + "|" + normalized_title_or_quote + "|" + (author or category). Before hashing, strings are lowercased, stripped of smart quotes/punctuation, and internal whitespace is collapsed (re.sub(r'\s+', ' ', text)). An SHA-256 digest of this canonical string is checked against an in-memory set. Variations in casing or spacing produce identical hashes and are safely deduplicated.

Why this unified schema and how do we prevent invented data?

We designed a 10-field polymorphic schema that spans both e-commerce items and literary quotes without synthetic fields. For Books, author and tags remain strictly None. For Quotes, price and rating remain strictly None. The unified field name_or_title anchors the core entity value in both paradigms.

What would you change to scale this for 1,000,000 pages?

1) Replace synchronous Requests with an asynchronous framework (Scrapy + Twisted or asyncio + aiohttp). 2) Distribute crawling using Celery with a Redis URL queue and Bloom filters for deduplication. 3) Rotate residential proxies and manage user-agent pools. 4) Stream data directly to cloud object storage (S3) or Parquet/Delta Lake on DuckDB rather than holding all records in RAM.

Assumptions & Limitations

  • Assumptions: The public practice sites remain static HTML without Cloudflare Bot Management or CAPTCHAs. Ratings conform to English numerals ('One' through 'Five'). Prices use the British Pound symbol (£).
  • Limitations: Single-process execution; polite crawling rate (1 req/sec) takes ~1-2 minutes for deep scraping; quotes dataset lacks numeric pricing/rating attributes, so those fields are naturally null in the consolidated model.

AI Assistance & Verification Disclosure (AI_USAGE.md)

1. AI Tools Used & Purpose

Anthropic Claude 3.5 Sonnet / OpenAI GPT-4o were utilized as code copilots for boilerplate generation, regex expression synthesis (e.g. currency pattern matching), and unit test scenario brainstorming.

2. Representative Prompts

  • "Write a regex in Python to strip varied currency symbols like £, $, € and parse clean floats."
  • "Draft a pytest test suite verifying rating normalization from text words ('Three') to 3."
  • "Generate a composite SHA-256 deduplication strategy for quotes and book titles."

3. Discovered AI Errors & Manual Corrections

• Relative URL joining error: The initial AI-generated code simply appended base_url + href, causing broken links for deep paths like catalogue/category/.... This was manually replaced with RFC-compliant urllib.parse.urljoin().

• Invented data trap: An early suggestion populated missing quote prices with 0.00. This violated the requirement never to invent data; corrected to strict None.

• Pagination infinite loop risk: The suggested Quotes scraper searched for a:contains("Next") which failed on localized versions; replaced with precise CSS selector li.next > a.

4. Output Verification Strategy

Every scraper output was verified against the live websites. We conducted manual spot checks on 20 random rows, executed automated pytest suites verifying edge cases, and generated the summary JSON report to confirm zero records were silently dropped without audit reasons.
